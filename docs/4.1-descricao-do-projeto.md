# 4.1 Descrição do Projeto

## O problema, na voz do cliente

> *"Às vezes fica difícil controlar os pedidos e saber quais sabores ainda temos disponíveis, principalmente quando tem bastante movimento."* 

## Propósito

Os pedidos e a quantidade de sorvetes disponíveis são controlados de forma manual. Quando há muitos clientes, pode ficar mais difícil saber quais sabores ainda estão disponíveis e quais pedidos já foram registrados. O **IceTech** foi pensado para ajudar a organizar essas informações e facilitar o atendimento da sorveteria.

## Objetivo

Com o sistema funcionando, os pedidos vão ficar registrados e será possível consultar os sabores disponíveis e acompanhar as quantidades em estoque, assim, o atendente consegue encontrar as informações com mais facilidade durante o atendimento.

## Quem usa

* **Atendente.** Registra os pedidos dos clientes e consulta os sabores disponíveis.
* **Gerente.** Cadastra os sabores, acompanha o estoque e consulta os pedidos realizados.

O cliente do projeto é o responsável pela sorveteria. Ele poderá acompanhar as informações do sistema e ajudar a verificar se as necessidades do estabelecimento estão sendo atendidas.

## Escopo

* O sistema cadastra os sabores disponíveis.
* O sistema registra os pedidos dos clientes.
* O sistema permite consultar os sabores disponíveis.
* O sistema atualiza a quantidade de produtos em estoque.
* O sistema permite consultar os pedidos realizados.

## Fora do escopo

* **Pagamento online**, porque nesta primeira versão o foco será organizar os pedidos e o estoque.
* **Sistema de entrega**, porque o projeto será voltado inicialmente para o atendimento dentro da sorveteria.
* **Controle financeiro completo**, porque essa parte pode ser adicionada em uma versão futura, caso seja necessária.

## Características principais

O sistema será acessado pelo navegador, com acesso restrito às funções de estoque, as informações devem ser rápidas  de consultar, principalmente nos horários de maior movimento.
